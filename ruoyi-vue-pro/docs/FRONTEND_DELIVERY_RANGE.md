# 顾客端配合：原价销售与配送范围

2026-11-20。顾客端为 `yudao-mall-uniapp`，由顾客端同事修改、联调及上传；服务器不检出该目录。部署验收见根目录 `DEPLOY.md`。

## 规则

- 停用会员等级优惠；不再因“白银”等等级打折。会员资料、历史订单及原优惠记录保留。
- 新订单仍为 `deliveryType=3` 店铺配送或 `2` 自提，`paymentMethod=2` 见面付款。
- 配送中心由 Admin 设置，当前正式自提点、直线半径 5000 米；≤半径免费配送，超出禁止配送，仍可自提。
- 使用收货地址地图位置，不使用手机当前位置。自提不受距离限制，旧订单不重算、不因新范围阻止履约。

## 地址接口

沿用 `/app-api/member/address/create`、`/update`、`/get`、`/list` 的原字段与调用方式；请求及读取响应增加两个可空数字：`latitude`、`longitude`，统一 **GCJ-02**。

1. 从顾客实际地图选点获得，不给顾客默认填门店位置，不要求手填经纬度；详细楼栋门牌仍可填写。
2. 两值成对提交，纬度 ±90、经度 ±180，不能为 NaN/无穷。
3. 兼容旧客户端：两个值都不传仍能保存地址，但不能店铺配送，需补选地图位置。
4. 旧客户端修改地区/详细地址但不传坐标时，后台清空旧定位；仅修改联系人、电话、默认标记可保留定位。
5. 地图选点取消或拒绝授权时不伪造位置。位置改变后重新保存地址并试算。

## 配送资格预检查

顾客登录后调用 `GET /app-api/trade/delivery/store-range?addressId=实际地址ID`，沿用当前顾客 Token 与租户请求头。成功示例：

```json
{
  "code": 0,
  "data": {
    "available": true,
    "pickUpStoreId": 5,
    "radiusMeters": 5000,
    "distanceMeters": 1800,
    "reasonCode": 0,
    "reason": "可配送"
  },
  "msg": ""
}
```

示例门店和距离不是顾客地址默认值。预检查不创建订单；不能配送也以外层 `code=0` 返回，读取 `data.available`、`reasonCode`、`reason`。鉴权/参数错误仍走原错误处理；地址缺少定位时距离为 null。

| reasonCode | 含义及处理 |
| --- | --- |
| 0 | 可配送，重新试算并展示后台金额 |
| 1011000099 | 超范围，提示“该地址超出5公里配送范围，请选择自提”，具体半径和文案以响应为准 |
| 1011000100 | 未选地址或无地图位置，引导选择/补定位，或选择自提 |
| 1011000101 | 中心未配置、停用或无有效定位，允许改选自提 |
| 1011000102 | 地址不存在、已删除或不属于当前顾客，重新选择自己的地址 |

按未取整距离判断，展示值向上取整为整数米。不用显示的“5.0公里”作为放行依据，不提交自行计算的距离，不允许顾客指定配送中心。

## 试算与下单

- 仍调用 `GET /app-api/trade/order/settlement` 和 `POST /app-api/trade/order/create`，店铺配送传持久化 `addressId`，不提交金额或距离。
- 试算成功增加 `data.deliveryRange`，结构同上；`data.address` 增加坐标。自提不检查半径，`deliveryRange` 为空，联系人/门店字段照旧。
- 超范围、缺定位、地址无效等在试算/创建中返回**外层非零业务 code**，使用上表代码，不生成订单或支付单、不扣库存。
- 后台在创建时重新校验地址与最新中心/半径，不能凭先前检查结果跳过。
- 切换地址、定位、配送方式、购物车或登录会话后丢弃旧响应；网络失败不能沿用旧的可配送状态。

## 前台工作指令

1. 去掉会员价及其产生的“直降”等展示，刷新商品结算接口；金额始终以后台为准。
2. 地址增加地图选点并保存坐标，旧地址引导补定位。
3. 确认页选地址后预检查并重新试算；不可配送阻止提交，提供“选择自提”入口，不静默改快递、不伪造坐标。
4. 处理下单时返回的同组业务错误，不能只检查按钮。
5. 验收范围内、正好5000米、5000米外、无定位、切地址、切自提及网络失败。使用隔离测试数据，不修改真实订单。
6. 完成真机联调后重新编译、上传顾客小程序；后端验收不等于小程序已更新。

Admin“设置 → 店铺配送范围”使用 `GET/PUT /admin-api/trade/config/store-delivery-range`，保存 `{ "pickUpStoreId": 实际门店ID, "radiusMeters": 5000 }`，沿用 `trade:config:query/save` 权限。顾客不调用管理接口。
